01 System Architecture & Wave 4 Parallel Topology

✓ What Worked Exceptionally Well

1. End-to-End Two-Stage Worker Orchestration With Crash Lease Recovery (A-016)

src/worker/job-runner.ts (`PR #38 @ 160ef88`) unified `A-003` ingestion, `A-004` capabilities, `A-005` opportunities, `A-006` scoring, and `A-007` match explanations into a single atomic SQLite WAL job loop that recovers abandoned leases after crashes and preserves any match a participant has already acted on.

2. Bilateral Consent Gate & Golden Arc Stage Synchronization (A-012)

Ariadne-Lane-A (`PR #34 @ baff161`) wired `POST /api/matches/:id/decision` through `classifyIntroTransition` so the stage Golden Arc and private Intro Room (`/me/matches/:id`) unlock if and only if both builders tap `Interested`, while withdrawal immediately locks rooms and vCards (`403`).

3. Need-to-Capability Vocabulary Bridge Lifting Surfaced Matches 2.1× (#38)

`NEED_LABEL_EXPANSIONS` in `src/matching/scorer.ts` bridged `A-005` need categories (`Frontend (React)`, `Backend services`) to concrete `A-004` capability claims (`React`, `Go`), raising surfaced matches on the 25-persona pool from `24` to `51` while keeping the contract's weights and anti-clone cap untouched.

4. Pre-Flight R-Gate & I-Gate Alignment on Pipelined Wave Boundary Accounting

Proactively aligning `Ariadne-PRR` and `Ariadne-INT` via Medusa switchboard before committing `v0.4.0` resolved the `Car 04-B` (`#5`, `PR #31`) boundary question up front (`State C = 3`, `t2 = 20:28:44Z`, `prs_merged = [34, 36, 30, 38]`).

⚠ What Didn't Work & Proven Fixes Enacted

1. Vocabulary Gap Between Generic Need Labels and Specific Capability Names

Initially, `A-005` emitted category-level need labels while `A-004` emitted specific language/framework names, causing `need_offer_fit` cosine to read `0` for valid pairs. Fix / Guardrail: Added PM/Arc-approved `NEED_LABEL_EXPANSIONS` in `PR #38` (`160ef88`) and shared it with `A-007`'s explanation cards.

2. Separate Stage 1 vs. Stage 2 Privacy Scrubbing Regexes (`#32` → `#36`)

Maintaining separate privacy detectors in Stage 1 and Stage 2 risked drift on phone numbers and ambiguous domain suffixes. Fix / Guardrail: `PR #36` (`b5ee8bc`) unified both stages onto `findPrivateSpans` in `src/matching/evidence-formatter.ts` with 26 dedicated tests.

3. DNS-Rebinding & Cross-Origin Forgery Risk on Local `/admin` Endpoints

Checking only the loopback socket IP (`127.0.0.1`) on `/admin` leaves a browser vulnerable to DNS rebinding or cross-site POSTs. Fix / Guardrail: `src/routes/admin.ts` (`PR #38`) enforces loopback `Host` header validation (`localhost`, `127.0.0.1`, `[::1]`) plus same-origin `application/json` checks (and `PR #39 @ 580b203` extended the same guard to `/api/stage/seed-toggle`).

4. Report `t8` Placeholder Timestamp vs. Actual GitHub Comment `created_at`

During `PR #37` review, `Ariadne-PRR` caught that pre-populating `t8` before posting the PR comment caused `t8` to differ from the GitHub comment's `created_at`. Fix / Guardrail: `Ariadne-Obsr` now posts the `O-Gate PASS` comment on the report PR first, reads its exact `created_at` UTC timestamp via `gh api`, and commits that exact timestamp into `metrics_schema.py` and the published HTML report.
