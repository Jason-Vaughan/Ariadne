# [feature] A-012: Mutual-introduction workflow

- **Issue ID:** `A-012`
- **Priority:** `P1`
- **Assigned Lane:** `Ariadne-Lane-A` (Builder A)
- **Milestone:** `Wave 3 — Exceptional Success (v0.3.0-m3)`
- **Dependencies:** `A-008`

## 1. Description
Implement the bilateral mutual-introduction state machine (`POST /api/matches/:id/decision`), GitHub ownership verification gate (`ownership_verified === true` via GitHub OAuth or bio challenge), private incoming-interest notification banner on `/me`, and the unlocked **Private Web Introduction Card / Room** (`/me/matches/:id`) when both participants click `Interested`.

## 2. Rationale
Ariadne's core promise is *"introduces you when you both agree."* No contact information may be disclosed and no introduction may fire without verified bilateral approval, and the web workflow must work 100% independently even if a participant does not use Discord.

## 3. Dependencies
- Depends on `A-008` (Match Cards UI and participant session).

## 4. Implementation Boundaries
- **In Scope:** `src/lib/intros/state-machine.ts`, `src/app/api/matches/[id]/decision/route.ts`, ownership verification prompt modal, unlocked Mutual Introduction Card on `/me`, and emission of `introduction.proposed`, `introduction.accepted`, `introduction.declined`, and `introduction.completed`.
- **Out of Scope:** Optional Discord bot delivery (`A-013`, which hooks into `introduction.proposed` / `introduction.accepted`).

## 5. Acceptance Criteria
- [ ] Clicking `Interested` requires `ownership_verified === true` (prompts 1-click GitHub OAuth or bio token check if not yet verified).
- [ ] Transitions match state deterministically (`candidate` → `proposed_by_a/b` → `mutual_accepted` → `completed`, or `declined`).
- [ ] Repeated clicks or retries are strictly idempotent and never produce duplicate events or duplicate introductions.
- [ ] Once `completed`, both participants see the unlocked **Mutual Introduction Card** displaying verified GitHub profiles, shared contact handle(s), cited repositories, and a copyable starter message.

## 6. Test Requirements
- State-machine and API concurrency/idempotency tests verifying: (a) unverified users cannot trigger outbound proposals (`403`), (b) unilateral interest does not reveal counterpart contact info, (c) bilateral interest unlocks the introduction card and emits `introduction.completed` exactly once, and (d) `Pass` transitions to `declined` without leaking rejection alerts.

## 7. Security & Privacy Considerations
- Enforce strict row-level authorization: only `participant_a` or `participant_b` of that specific match can call `POST /api/matches/:id/decision`.

## 8. Expected Demonstration Impact
Unlocks **Exceptional Success (`M3`)**: two consenting attendees tap `Interested` on their phones, receive an immediate mutual introduction card, and trigger a glowing emerald connection on the stage visualizer.
