# [feature] A-013: Discord event bot

- **Issue ID:** `A-013`
- **Priority:** `P1`
- **Assigned Lane:** `Ariadne-Lane-A` (or `Ariadne-Lane-B` in Wave 3)
- **Milestone:** `Wave 3 — Exceptional Success (v0.3.0-m3)`
- **Dependencies:** `A-012`

## 1. Description
Implement the dedicated Ariadne Event Discord adapter (`src/lib/discord/bot.ts` and `/api/discord/interactions`) that delivers private match proposals to opted-in participants and creates a mutual introduction thread or DM when both participants approve—while preserving the `A-012` private web fallback whenever Discord delivery is unavailable.

## 2. Rationale
Hackathon attendees frequently coordinate in an event Discord server. Facilitating approved introductions directly in Discord creates an immediate, frictionless handoff into a real conversation.

## 3. Dependencies
- Depends on `A-012` (mutual-introduction state machine and bilateral approval verification).

## 4. Implementation Boundaries
- **In Scope:** `src/lib/discord/bot.ts`, Discord REST v10 message/thread dispatch, signed interaction webhook `/api/discord/interactions` (supporting `[Accept Intro]` / `[Pass]` buttons), and automatic graceful fallback to the web introduction card on `403 Cannot send messages to this user`.
- **Out of Scope:** Modifying or sharing credentials with TangleClaw's privileged Operator Discord bot.

## 5. Acceptance Criteria
- [ ] Uses a dedicated `ARIADNE_DISCORD_BOT_TOKEN` completely isolated from TangleClaw's Operator gateway.
- [ ] Sends private match notifications **only** to participants who explicitly linked their Discord identity and opted in.
- [ ] When both participants approve, opens a private Discord thread/DM introducing both builders with their matched repositories and suggested first topic.
- [ ] If a participant has no Discord linked or blocks DMs, catches the error cleanly, marks `channel = 'web'`, and completes the introduction via the `A-012` web view with zero user-facing errors.

## 6. Test Requirements
- Unit tests mocking Discord REST API `200` success and `403/429` failure responses, verifying that failed Discord delivery still completes the web introduction state cleanly, plus Ed25519 signature verification tests on `/api/discord/interactions`.

## 7. Security & Privacy Considerations
- Verify `X-Signature-Ed25519` and `X-Signature-Timestamp` headers on all incoming Discord interaction webhooks.
- Never post private match proposals in a public Discord channel without explicit bilateral opt-in.

## 8. Expected Demonstration Impact
Completes the full **Exceptional Success (`M3`)** stretch demonstration: two participants approve a match and immediately receive a live Discord introduction thread crafted by Ariadne.
