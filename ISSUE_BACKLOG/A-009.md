# [feature] A-009: Live event stream

- **Issue ID:** `A-009`
- **Priority:** `P0`
- **Assigned Lane:** `Ariadne-Lane-D` (Builder D)
- **Milestone:** `Wave 1 — Minimum Success (v0.1.0-m1)`
- **Dependencies:** `A-001`

## 1. Description
Implement the append-only structured event persistence publisher (`src/lib/events/publisher.ts`) and Server-Sent Events (SSE) streaming endpoint (`GET /api/events/stream`) supporting `Last-Event-ID` / `?after=<seq_id>` catch-up replay and aggregate KPI snapshot bootstrap (`GET /api/events/summary`).

## 2. Rationale
The 16:9 stage visualizer and participant progress indicators need real-time, verifiable updates that survive serverless connection recycling or brief venue Wi-Fi drops without losing state or fabricating activity.

## 3. Dependencies
- Depends on `A-001` (`PublicEventEnvelope`, `EventType` catalog, and `domain_events` table).

## 4. Implementation Boundaries
- **In Scope:** `src/lib/events/publisher.ts`, `src/lib/events/sanitizer.ts`, `src/app/api/events/stream/route.ts`, and `src/app/api/events/summary/route.ts`.
- **Out of Scope:** Stage visualizer canvas rendering (`A-010`, `A-011`).

## 5. Acceptance Criteria
- [ ] `publishDomainEvent()` atomically persists the event with a monotonic `seq_id` after running the public-payload privacy sanitizer.
- [ ] `GET /api/events/stream` streams standard SSE frames (`id: <seq_id>\nevent: <event_type>\ndata: <json>\n\n`).
- [ ] Reconnecting with `Last-Event-ID` or `?after=<seq_id>` replays all missed events in exact monotonic order with zero duplicates or gaps.
- [ ] Zero simulated or synthetic heartbeat events are disguised as agent activity (keepalive comments `: keepalive\n\n` only).

## 6. Test Requirements
- Unit/integration tests verifying monotonic `seq_id` ordering, `Last-Event-ID` catch-up replay, and strict stripping of unconsented `github_username`/`avatar_url` fields by the sanitizer.

## 7. Security & Privacy Considerations
- The SSE stream reads **exclusively** from the pre-sanitized `public_payload` column.
- `introduction.declined` increments only an aggregate counter and never broadcasts the declining participant pseudonyms on the public stream.

## 8. Expected Demonstration Impact
Forms the real-time backbone of the stage display: every QR scan, GitHub analysis, match evaluation, and mutual introduction appears on the projector screen within 1 second of occurring.
