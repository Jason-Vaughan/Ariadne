# [feature] A-016: Continuous rematching

- **Issue ID:** `A-016`
- **Priority:** `P2`
- **Assigned Lane:** `Ariadne-Lane-C` (Builder C)
- **Milestone:** `Wave 3 — Stretch (v0.3.0-m3)`
- **Dependencies:** `A-006`, `A-007`

## 1. Description
Implement background continuous rematching (`src/lib/scoring/rematcher.ts`) so that when a new participant joins and completes `profile.analysis.completed`, existing participants whose top-3 match slate improves by `>= 5 points` (or who previously had fewer than 3 matches) automatically have their candidate matches updated without re-submitting their profile.

## 2. Rationale
Early event arrivers (the first 1–3 attendees to scan the QR code) initially see a sparse pool. Continuous rematching ensures early adopters receive fresh, high-value matches as the room fills up.

## 3. Dependencies
- Depends on `A-006` (Match Scoring Engine) and `A-007` (Match Proposal Agent).

## 4. Implementation Boundaries
- **In Scope:** `src/lib/scoring/rematcher.ts`, debounced rematch trigger on new `profile.analysis.completed` events, preservation of any existing `proposed` / `accepted` / `declined` matches (never overwrite a match a user already acted on), and per-participant LLM evaluation cap (`max 3 new LLM evaluations per entrant`).
- **Out of Scope:** Spamming repeated notifications; notification cap enforced at max 1 "New top match discovered" alert per 15 minutes.

## 5. Acceptance Criteria
- [ ] When Participant $N$ finishes profile analysis, `rematcher` scores Participant $N$ against all active `ready` participants deterministically.
- [ ] Triggers `A-007` LLM explanation generation **only** when Participant $N$ enters an existing participant's top-3 slate (and `score >= 45`).
- [ ] Never clobbers or resets a match where either participant has already clicked `Interested` or `Pass`.
- [ ] Respects strict notification cooldowns so early participants are never spammed.

## 6. Test Requirements
- Unit tests verifying: (1) early participant with 0 matches receives a match when a compatible 2nd participant joins, (2) acted-upon (`proposed`/`declined`) matches are preserved untouched, and (3) LLM calls are bounded to top-3 threshold entrants only.

## 7. Security & Privacy Considerations
- Exclude any participant with `consent_status === 'withdrawn'` from rematching passes immediately.

## 8. Expected Demonstration Impact
Makes the live room dynamic effortless: the Operator can scan the QR code first when the room is empty, and automatically receive top matches as judges and attendees scan in later.
